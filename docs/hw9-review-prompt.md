## Требования и существенные проверки

1. Middleware использует `context.WithTimeout`, передает контекст через `r.WithContext` каждому API-обработчику. По умолчанию 2 секунды, флаг `-request-timeout` позволяет проверить короткий срок. Ранний родительский дедлайн не продлевается. Отмена и дедлайн дают единый JSON и статус 504: `{"error":"request timed out"}`. Проверь все API-операции, успешный возврат сервиса после отмены контекста, медленное тело запроса и сохранение прежних ошибок 400/409/500.
2. `GET /api/reports/summary?from=YYYY-MM-DD&to=YYYY-MM-DD` разбирает диапазон, передает контекст сервису и возвращает суммы категорий. Неверная дата или порядок дают 400. Сохранен прежний JSON ДЗ 7 с полями `from`, `to`, `categories`, `total`; пример JSON в условии не требует ломать существующий контракт.
3. Сервис получает категории с расходами в диапазоне, запускает по одной горутине на категорию, использует `sync.WaitGroup`. Доступ к результатам без гонок; порядок стабилен. Категории без расходов не добавляются. Два граничных дня включаются, переходы часового пояса не теряют последний день. Пустой ответ корректен.
4. Каждая операция БД использует контекст. Отмена или ошибка прерывает соседние работы; метод дожидается всех работников до возврата, сохраняет причину ошибки и не возвращает/кеширует частичный отчет. Проверь не только дедлайн, но и отмену клиента и отказ одной категории.
5. Heartbeat работает в отдельной горутине через `time.Ticker` каждые 400 мс. Тикер останавливается, горутина завершается до возврата при успехе, ошибке и отмене. Быстрый отчет может не успеть выдать первый тик. При отмене есть лог завершения. После ответа сообщения больше не появляются.
6. Кеш отчетов сохраняет формат ключа и полезной нагрузки, TTL 30 секунд и прежнее поведение при отказе Redis. Попадание в кеш не запускает расчет. Документированное отставание кеша до 30 секунд и разные SQL-снимки отдельных категорий не считать дефектами сами по себе: общего снимка условие не требует. Сумма total должна соответствовать категориям ответа.
7. Сохранены бюджетное правило и его атомарность, кеш бюджетов, независимость экземпляров, фабрика Ledger, разделение слоев ДЗ 8. Удаленный репозиторный агрегат заменен сервисным расчетом, дублирования алгоритмов нет. Новые абстракции должны иметь текущих потребителей. Сохранена совместимость с Go 1.22, новые библиотеки не добавлялись.
8. README содержит пример отчета, настройку таймаута, статус 504 и воспроизводимую проверку отмены SQL через блокировку тестовой таблицы без искусственных задержек в бизнес-коде.

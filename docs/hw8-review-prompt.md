## Требования задания

1. Выделить доменные сущности, их валидацию и минимальные контракты хранения. Бюджеты: добавление/обновление, поиск по категории, список. Расходы: добавление, список, сумма по категории.
2. Изолировать SQL в репозиториях PostgreSQL, реализующих доменные интерфейсы. Нет зависимости от HTTP и Gateway.
3. Вынести в сервис валидацию, нормализацию и бюджетное правило: сумма расходов категории за период плюс новый расход не превышает лимит. Сервис работает только через внедренные доменные контракты.
4. Фабрика Ledger читает конфигурацию, открывает подключения, собирает зависимости и возвращает интерфейс сервиса, функцию закрытия и ошибку. Принимает контекст и передает его в стартовый Ping. Миграции внутри фабрики запрещены. Gateway логирует ошибку старта и завершается.
5. Gateway получает готовый сервис, передает его HTTP-обработчикам через конструктор и вызывает методы интерфейса. Не импортирует SQL, pgx и репозитории. DTO, HTTP-коды и формат ошибок сохраняются.
6. Зависимости направлены внутрь, циклов нет. Сохраняются прежние тесты и curl-сценарии. README описывает структуру и инициализацию. Сдаваемая версия должна быть закоммичена и опубликована по доступной проверяющему ссылке.

## Что проверить в коде

- `ledger/domain`, `ledger/service`, `ledger/app.go`, `ledger/internal/repository/{pg,memory,cached}`, `gateway/main.go`, `gateway/internal/api` и `ledger/cmd/ledger`.
- Проверка бюджета действительно находится в сервисе, а транзакция БД охватывает чтение бюджета, сумму расходов и вставку. Сохранились блокировки существующего бюджета, конкурентные расходы не используют один остаток дважды. Ошибка, отмена и паника освобождают ресурсы и откатывают запись.
- Атомарная загрузка бюджетов, порядок блокировок при нескольких категориях, периоды month/year/пустой, округление до копеек, локальные даты и порядок выдачи.
- Кеш не участвует в проверке лимита. Сохранились TTL 30 секунд, сброс списка бюджетов, чтение из PostgreSQL при отказе Redis и ограничения времени. Документированное отставание кеша из ДЗ 7 само по себе не считать новой ошибкой.
- Отсутствие изменяемого пакетного хранилища; независимость экземпляров. Ошибка фабрики не оставляет частично готовый сервис или незакрытые подключения. Закрытие после завершения HTTP-запросов и повторный вызов функции закрытия.
